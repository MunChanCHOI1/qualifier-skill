# Submission Readiness

Before artifact confirmation, apply [Boundaries](../SKILL.md#boundaries) and reuse current evidence.

- Match mandatory criteria and required files/paths/formats to saved artifacts and observed results. Check execution instructions, dependencies, and contents against the implementation; disclose unexecuted clean-environment checks.
- Review final changes for unrelated edits, broken references, and sensitive content. Preserve supplied files. For unseen editor changes or save conflicts, ask the participant to check; preserve both versions until resolved.
- Follow actual deadlines and official handoff steps. A preview listing is not a complete submitted-file inventory unless the platform guarantees it.

## Judgment

| Judgment | Condition |
| --- | --- |
| **제출 준비됨** | Mandatory artifacts, behavior, sufficient verification, and saved state are confirmed. |
| **수정 필요** | A mandatory criterion fails, a required artifact is missing, or a known save conflict remains. |
| **확인 불가** | Missing evidence or access prevents judging a mandatory criterion. |

A known failure takes precedence over uncertainty; report both. Optional unexecuted checks alone do not block readiness. Fix and recheck when feasible and still authorized.

Report judgment/reason, artifact locations and execution method, required-check results, limits, and the participant's next step concisely. While still in permitted task work, recap the implemented input-to-output flow and consequential design limits using the existing briefings; do not introduce quiz predictions or answer scripts. The participant checks the preview, confirms the artifact, and verifies the final receipt. Readiness is not a submission receipt; assistance ends at the cutoff in Boundaries.
